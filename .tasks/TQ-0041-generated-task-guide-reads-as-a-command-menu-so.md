## Finding

`.tasks/AGENTS.md` (generated by `taskGuide` in `agents.go`) documents the
lifecycle as three topic headings full of command listings:

    ## Pick up work
        tq ready --json                 tasks that are unblocked and unclaimed
        tq show <id> --json             the full task, body included
        tq move <id> in-progress        claim it

That is the same shape as `## Find things` and `## Create and change`, which
are genuinely optional. Nothing marks the claim/note/close steps as a sequence
an agent must complete rather than a menu it picks from.

## How it fails

Observed: `/implement TQ-0007` in this repository. The agent ran `tq show`,
read the ticket, and went straight to editing source. TQ-0007 stayed `todo`
for the whole session — no claim, and on the same reading no `tq note` or
`tq done` at the end either.

Two contributing causes:

- Neither document states the lifecycle as a requirement. The guide lists
  commands under topic headings, and the root `AGENTS.md` bullet that points
  at it, `Use this project for task management`, names a tool without naming
  an action or a moment. The guide is the one that should carry the steps: it
  is the document the root includes with `@.tasks/AGENTS.md`, so it is already
  in context in full.
- A generic `/implement` skill supplies an explicit ordered procedure
  (implement, test, review, commit). When one source gives steps and another
  gives vocabulary, the steps win.

## Suggested fix

Keep one home for the workflow and one nomenclature for reaching it.

- In `agents.go`, rewrite the guide's lifecycle sections in the imperative:
  claim before the first edit, note at checkpoints, close before reporting
  completion. Keep the command listings as the how. This is the single source
  of truth for how work is tracked — the detail belongs here, not in the root
  document.
- Regenerate `.tasks/AGENTS.md` and commit it.
- The root `AGENTS.md` reaches the guide with an `@.tasks/AGENTS.md` include,
  which is this repository's nomenclature for pulling a document into agent
  context. Because the include delivers the whole guide, the root document
  needs only a minimal pointer — spelling the lifecycle out again there would
  duplicate it and give the two copies room to drift. Replace the vague
  `Use this project for task management` bullet with a one-line pointer to the
  `Task management` section, and leave the steps to the guide.

A `PreToolUse` hook that blocks edits without an in-progress task would enforce
this mechanically, but that is a separate change and out of scope here.
